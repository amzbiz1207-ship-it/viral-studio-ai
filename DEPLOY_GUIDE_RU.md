# Viral Studio AI — обновление и установка

**Версия:** 3.0 (личный прототип, не многопользовательский коммерческий сервис).

## Что поменялось

- Исправлена навигация между разделами и добавлены кнопки «Назад» / «Инструменты».
- Проекты создаются с отдельными профилями, а не копируют чужую нишу.
- Планы, статусы, библиотека и метрики сохраняются в SQLite (локально) либо Supabase (в облаке).
- Новые результаты автоматически добавляются в библиотеку; дубликаты видео и метрик не размножаются.
- Экспорт Markdown, Word и PDF с понятными именами файлов.
- Поиск YouTube: конкретизированные запросы, фильтры по просмотрам и сроку, короткие видео; результаты анализа можно открывать сразу из поиска.
- API Gemini и опциональный DeepSeek. Резервная модель используется только при подключённом ключе и временном сбое основной.
- Раздельные настройки языка интерфейса, языка материала и языка промптов в студии. Промпты на английском по умолчанию.
- Уточнены демонстрационные хуки, добавлен статус «Готово к публикации».

## 1. Резервная копия прежде всего

1. В существующем сайте, если возможно, открой «Настройки» → «Скачать все данные JSON». Это последняя возможность сохранить материалы текущей сессии.
2. Сохрани на компьютере прежний ZIP репозитория.
3. Перед загрузкой нового набора файлов не удаляй Streamlit Secrets, особенно `APP_PASSWORD` и API-ключи.

## 2. Обнови GitHub

В распакованном ZIP все файлы уже находятся на одном уровне. Загрузи **содержимое папки**, а не папку целиком, в корень репозитория `viral-studio-ai`, где лежит `app.py`. Подтверди **Commit changes**.

Важно: новыми являются `storage.py`, `exports.py`, `test_storage_export.py`, `DEPLOY_GUIDE_RU.md`, `.gitignore`. Нужно загрузить и их, иначе сайт не запустится. `requirements.txt` тоже изменён.

## 3. Настрой Streamlit Secrets (не в GitHub)

Открой `share.streamlit.io` → `viral-studio-ai` → `⋮` → `Settings` → `Secrets`.

Ниже **пример имён**; реальные значения вставляй только в Secrets. Существующие строки сохрани, не перезаписывай их по неосторожности.

```toml
APP_PASSWORD = "YOUR_PRIVATE_PASSWORD"
GEMINI_API_KEY = "YOUR_GEMINI_API_KEY"
GEMINI_MODEL = "gemini-3.8-flash"
YOUTUBE_API_KEY = "YOUR_YOUTUBE_DATA_API_KEY"
# Необязательно: резервный текстовый провайдер
# DEEPSEEK_API_KEY = "YOUR_DEEPSEEK_API_KEY"
```

`GEMINI_MODEL` должен совпадать с реально доступной моделью твоего ключа. Если Google сообщает, что конкретная модель недоступна, проверь название и права в Google AI Studio. Не публикуй секретные ключи в переписках/скриншотах.

## 4. Обязательно для долговременного хранения на Streamlit Cloud: Supabase

**Без этого шага приложение использует SQLite.** SQLite сохраняет изменения после обновления вкладки, пока данные остаются на том же сервере. Но **Streamlit Community Cloud может стереть локальные файлы при перезапуске, redeploy или перемещении приложения**. Не рассчитывай на SQLite как постоянную облачную базу.

1. Создай личный проект на `https://supabase.com/`.
2. Открой **SQL Editor**, выполни:

```sql
create table if not exists public.viral_studio_state (
  owner text primary key,
  payload jsonb not null,
  updated_at timestamptz default now()
);
alter table public.viral_studio_state enable row level security;
revoke all on table public.viral_studio_state from anon, authenticated;
grant select, insert, update on table public.viral_studio_state to service_role;
```

3. В Supabase Settings → API Keys найди **Project URL** и **service_role / server-side secret key**. Это чувствительный ключ с широкими правами; **никогда не помещай его в GitHub или публичный интерфейс**.
4. Добавь в Streamlit Secrets **две дополнительные строки**:

```toml
SUPABASE_URL = "https://YOUR_PROJECT.supabase.co"
SUPABASE_SERVICE_ROLE_KEY = "YOUR_SERVER_SIDE_SECRET"
```

5. Сохрани, перезапусти приложение. В «Настройках» должна появиться строка **«Подключено постоянное облачное хранилище Supabase»**.
6. Создай тестовый проект, сохрани видео, поставь статус публикации, затем обнови страницу и проверь. После этого в Streamlit сделай **Reboot** и проверь повторно.

**Важно:** этот способ предназначен для **одного владельца**, защищённого одним паролем. Для продажи многим клиентам нужны отдельные учётные записи, правила доступа к данным, учёт квот, платежи и серверная авторизация. Не выдавай эту версию за готовый многопользовательский SaaS.

## 5. Проверка после установки

1. Запустить Streamlit и войти по паролю.
2. В «Анкета и проекты» создать новый проект. Он должен иметь пустые поля, а не чужую тематику.
3. Перейти «План на неделю» → создать шаблон → изменить статус → перейти назад → обновить вкладку. Проверить сохранение.
4. Найти видео через YouTube API; если подходящих нет, снизить порог просмотров. Результат может быть пустым, и это нормально.
5. Сохранить ролик и проверить его в библиотеке после перезагрузки.
6. Создать сценарий и скачать его в Word, PDF, Markdown. Проверить все три файла.
7. Добавить метрику ролика два раза: должна остаться одна запись. Удалить запись отдельной кнопкой.
8. Проверить DeepSeek только если создан собственный ключ и разрешено передавать этому поставщику текст запроса.

## Проверенные ограничения

- Нельзя автоматически получать покадровое видео, удержание аудитории и статистику Instagram/TikTok из одного YouTube Data API ключа.
- Короткий ролик до 180 секунд — лишь кандидат на Shorts; метаданные API не гарантируют принадлежность к Shorts.
- Просмотры за день **с момента публикации** — среднее, а не фактическое ускорение просмотров.
- Точность научных фактов и языковую однородность материалов AI всё ещё нужно проверять.
- DeepSeek может быть платным и также может испытывать перегрузки.
- При недоступной облачной базе приложение выводит ошибку вместо тихого сброса на пустой профиль.

## Локальный запуск для разработчика

```bash
python -m pip install -r requirements.txt
streamlit run app.py
python -m unittest -v test_core test_studio test_storage_export
```

Секреты задаются переменными окружения либо в `.streamlit/secrets.toml`, который не должен попасть в GitHub.
